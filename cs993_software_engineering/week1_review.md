# week 1 review questions

1. Select the benefits of following a software engineering approach.
   - Capture what stakeholders want

   - Enable efficient communication in the development team

   - Provide a process through which software can be delivered

2. What might happen if a development team is not communicating properly with a customer?
   - The customer may be unhappy with final product

   - The customer may start to distrust the development team

3. A lone developer has built a piece of software quickly, without thinking about the future or other developers. What issues might be present in the software?
   - No comments in the code, making it hard for other developers to understand the software

   - Variable names that do not make sense to another person

   - Bad architecture design, where the code has evolved rather than be clearly thought out

   - Long-term cost overruns, due to additional work needed to understand the software and improve it.

4. What should be shared within a development team?
   - Internal structure of software

   - Interfaces between components

   - Progress and issues.

5. Select the statements that are correct concerning programming interfaces.
   - Changing them within an established piece of software might require a significant amount of work

   - Programming interfaces describe the possible connections between different functions.

6. Select the reasons why a developer might build prototype programs that are not for users or customers.
   - To understand the functionality of computer hardware

   - To understand software frameworks

   - To allow performance testing needed to understand the behaviour of finished software under load Verify that an architecture approach is valid.

7. What are the normal motivations for sharing a user interface design or partially working application with a user or customer?
   - Provide an opportunity to understand what features are needed in the application
   - Discuss the user interface design and associated functionality.

8. When might it be a good idea to build up from low-level functionality towards a high-level user interface?
   - When hardware drivers have to be written

   - When data need to be read from or written to a database or other data storage format.

9. When might building down from a user interface implementation be a good software development strategy?
   - When low-level hardware drivers have been written

   - When the software frameworks that are being used have been understood

   - When low-level data serialisation and deseralisation code has been written.

10. Order the software development lifecycle steps for one iteration.
    1. → Capture user requirements
    2. → User interface design
    3. → High-level design
    4. → Low-level design
    5. → Implement the program
    6. → Test the implementation
    7. → Deploy and operate the program.

11. What should implemented software features match?
    - User requirement - what was requested, who requested it and why
      Validation test - verification that the feature is working as expected

    - Release contents - requested features are present

    - Release contents - additional unwanted features are not present.

12. Why is the waterfall lifecycle no longer used for most software development projects?
    - Requirements may no longer be suitable when software is delivered
    - Stakeholders cannot influence the development direction as much as hoped.

13. When using a plan-driven approach, such as the V-lifecycle, what is fixed?
    - The requirements.

14. How are prototypes used within the Spiral lifecycle?
    - They are used to understand architecture and development issues

    - They are used to demonstrate concepts or design to the user/customer.

15. Select the motivations for the Agile Manifesto:
    - Working software should be more important than comprehensive documentation

    - Individuals and interactions should be more important than processes and tools

    - Customer collaboration should be more important than contract negotiation.

16. Considering an Agile software lifecycle, what is fixed?
    - The development team resources

    - The schedule for the update.

17. Match the stages of Agile Scrum with the descriptions.
    - Product backlog → A collection of feature definitions to be considered for the project as a whole.
    - Sprint Backlog → A collection of feature definitions to be addressed during a sprint
    - Development Sprint → A period of software development, which is typically 2 to 4 weeks long
    - Scrum iteration → A short time period (often 24 hours), during which developers work on tasks
    - Release iteration → A functional release iteration, which includes feature that have been constructed during the sprint
